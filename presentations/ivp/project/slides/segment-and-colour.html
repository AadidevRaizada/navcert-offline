TIME: 50 seconds. Units 4, 6, 7. SAY: Black-and-white mode needs a threshold. A global one fails: there is no value that keeps faint ink in the dim corner and clean paper in the bright one. SAY: Otsu is the textbook answer, the threshold that maximises between-class variance. It is optimal when the histogram has two clean peaks. A light gradient smears the paper into a wide band, and Otsu cannot separate ink from the dark side. In the app's Lab on the sample certificate Otsu picks T equals 175, and the shadowed corner turns black. SAY: So the app compares every pixel with the Gaussian mean of its own 35 by 35 neighbourhood, minus 11. That is adaptive thresholding. On my synthetic shadow captures, rectified with true corners, OCR character error is 34.2 percent for a global threshold, 39.2 percent for Otsu and 0.05 percent for adaptive. After CLAHE plus a median the same three score 33.6, 40.2 and 0.40 percent. SAY: On the binary page, the Lab labels connected components, 4-connectivity breaks diagonal strokes, 8 keeps characters whole, and runs opening, closing and boundary extraction. SAY: Colour: in HSV, hue separates the red stamp from black ink whatever the lighting. That is colour slicing, Unit 7. CUE: the animation sweeps a global threshold, drops the Otsu value computed from the histogram, then shows adaptive. The animation's Otsu value is computed live from a generated page, so it differs from the 175 in the app. BACK-POCKET: Why does Otsu fail under uneven lighting? A shadow shifts the background level, so no single T keeps both regions. BACK-POCKET: Stamp detection: HSV, hue band plus minimum saturation; red wraps around hue 0 so use two bands. BACK-POCKET: m-connectivity uses diagonals only when the shared 4-neighbours are not foreground, removing 8-connectivity's double paths. BACK-POCKET: The adaptive result is the oracle case: the page was rectified with true corners so thresholding is isolated from detection.
