# AI-course experiments (synthetic data only)

Three small, reproducible experiments that connect NavCert Offline to the Artificial Intelligence syllabus. Every input is generated by these scripts. No certificate image or certificate text from the private corpus is read or stored.

```powershell
ml\.venv\Scripts\python.exe ml\ai_eval\run_all.py                          # writes ml/ai_eval/results.json
ml\.venv\Scripts\python.exe -m unittest discover -s ml\ai_eval -v          # 14 tests
```

Python 3.12, NumPy and OpenCV from the existing `ml/.venv`. No extra packages. The full run takes about 20 seconds on a laptop CPU.

| Script | Syllabus unit | Question it answers |
| --- | --- | --- |
| `csp_consistency.py` | Unit 4, CSP | Can hard constraints between fields (expiry after issue, port in a gazetteer, authority looks like an organisation) repair wrong first-choice candidates? |
| `ocr_search.py` | Unit 2, search | How does the app's greedy dictionary scan compare with uniform-cost search and A* over a dictionary trie? |
| `quality_tree.py` | Unit 5, decision trees | How does the app's hand-written dark/bright/blur tree compare with a CART tree learned from labelled examples? |

## 1. Field consistency as a CSP

Variables are the five fields. Each domain holds the candidate spans a rule extractor would propose, in priority order, plus `None` (abstain). Unary constraints are enforced first (node consistency). Backtracking then uses MRV variable ordering, forward checking and branch-and-bound that prefers filling more fields with higher-priority candidates.

The test generator creates 2,000 synthetic candidate sets. Each set gets one of seven distractor types: clean, equipment date above the real expiry, swapped issue/expiry, person's name under "Place of issue", noise line as authority, truncated OCR year, and a wrong date that still satisfies every constraint.

| Measure (seed 152, n = 2,000) | Greedy first candidate | CSP solver |
| --- | --- | --- |
| Field accuracy | 80.3% | 97.2% |
| Whole-record exact | 16.4% | 86.2% |
| Records satisfying all constraints | 30.2% | 100% |
| "Consistent but wrong date" cases fixed | 0 / 276 | 0 / 276 |

Mean search nodes per case: 10.4 with MRV + forward checking, 11.0 static order + forward checking, 11.6 static order without forward checking (0.58 backtracks per case).

Read these numbers as a demonstration of the mechanism. The generator decides how often each distractor appears, and five of the seven distractor types violate a constraint by design. The last row is the important limit: constraints only catch errors that break a constraint.

## 2. OCR post-correction as search

`app_correct` is a line-by-line port of `OcrTextCorrector.correctWord` and reads its dictionary (206 words) from the Kotlin source. It passes the same cases as `OcrTextCorrectorTest.kt`.

`search_correct` runs best-first search over a 772-node trie of the same dictionary. The state is (characters of the noisy word consumed, trie node). Known OCR confusions cost 0.4 (0/o, 1/l, 5/s, 6/g, 8/b, c/e, rn/m, cl/d, li/h, vv/w). Other edits cost 1. UCS orders by g(n). A* adds h(n) = 0.4 × |remaining characters − nearest completion length|, which is admissible and consistent.

| Synthetic noise (seed 152) | App greedy scan | UCS | A* |
| --- | --- | --- | --- |
| Digit confusions, 144 words: recovered | 0% | 100% | 100% |
| Letter/split-glyph confusions, 179 words: recovered | 72.1% | 100% | 100% |
| Miscorrections (both sets) | 0% | 0% | 0% |
| Mean work per word | 206 Levenshtein evaluations | 206.4 / 237.2 nodes | 68.1 / 74.0 nodes |
| 34 maritime out-of-vocabulary words changed | 1 | 1 | 1 |

Findings:

- The app's confusion map never fires. `correctWord` returns early for any word that contains a digit, so `d0cument` is never normalised. Removing that guard alone recovers all 144 digit-confusion words in this test.
- A* expands about 3× fewer nodes than UCS (68.1 vs 206.4 and 74.0 vs 237.2) for the same answers.
- Every method turns `manning` into `scanning`, because the dictionary has no maritime vocabulary. In the app, correction runs before field extraction, so a title such as "Minimum Safe Manning Certificate" written in mixed case is at risk. All-caps titles are protected by the uppercase guard.
- Both app findings are now fixed in `OcrTextCorrector.kt`: digit look-alikes are normalised inside mixed tokens (identifiers, all-caps codes, dates and ordinals stay protected) and the dictionary carries maritime vocabulary. `OcrTextCorrectorTest.kt` reproduces both bugs. The numbers in this section describe the app before that fix.
- The search methods score 100% partly because the noise model and the cost model share the same confusion list. That result shows the mechanism works, not that it would reach 100% on real OCR output.

## 3. Capture quality as a decision tree

`quality_tree.py` draws 240 synthetic pages of random glyphs at the app's 1,600 px analysis size. It degrades them in known ways (dark, bright, blurry, good), adds sensor noise, and computes the same two features as `DocumentScanner.measureQuality`: mean grey level and Laplacian variance. A CART tree (Gini, depth ≤ 3) is trained on 144 pages and tested on 96.

| Test split (96 pages) | Hand tree (55 / 220 / 65) | Learned CART tree |
| --- | --- | --- |
| Accuracy | 78.1% | 92.7% |
| Blurry pages caught | 5 / 22 | 20 / 22 |
| Good pages accepted | 22 / 25 | 20 / 25 |

Learned tree: `mean_gray < 97.0 → dark`; else `mean_gray ≥ 218.7 → bright`; else `laplacian_var < 267.7 → blurry`, otherwise good.

Sensor noise raises Laplacian variance, so a fixed blur threshold of 65 lets noisy, blurred pages through. The learned thresholds belong to this generator and this resolution. They are not a recommended replacement for the app's values; calibrating on real phone captures is the next step.
